Observed from original instructions, not inferred C++ types:

  preserves a guest stack word; `MOV EAX,[ESI+4]` reads a 32-bit guest word.
- The first branch sets `ECX=0` when that word is zero, otherwise loads
  `ECX=[EAX]`. The original pushes `EAX`, `ECX`, an address formed by

- The original `CALL 0x000E1150` is at `0x00012156`; the original callee has
  a `RET 16` instruction at `0x000E11DC`. It is **not** a proof of any
  native C++ prototype, lifetime, register preservation, or callee output.
- After that call, the original rereads `[ESI+4]`, pushes the result, and
  executes a direct `CALL 0x002EA018` at `0x0001215F`. The 36-byte caller
  has no ordinary `RET` after this call; its eventual exit is unresolved.

## Verification and quarantine

Use `python3 scripts/verify_20261106_00012140_call_edges_xbe.py --xbe /private/path/default.xbe`
with the user's original binary **outside the public repository**. This
verifies the caller's complete body digest, selected exact instruction bytes,
two `E8` destinations, the callee's `RET 16` opcode and mutation controls.

**Important unresolved provenance:** The inventory's stated full body SHA-256
for `0x000E1150` does **not** match a contiguous byte range beginning there
(up to 2,048 bytes) in the authenticated retail XBE. This may involve
noncontiguous function chunks or an extraction convention; no full-callee
provenance claim is made here. Investigate the original function extent and
hash generation before changing that canonical draft or claiming an
Xbox-verified calling convention. The existing `FUN_00012140` C++ draft is
left unchanged with `ABI_UNVERIFIED`, and no guest address is converted to a
native host pointer as part of this review.
