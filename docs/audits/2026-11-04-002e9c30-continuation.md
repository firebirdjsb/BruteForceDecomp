# 0x002E9C30 bounded source continuation

The earlier five heap-call declaration repairs deliberately held this function:
its draft omitted four stores after a falsely non-returning call. This separate
repair restores those stores rather than hiding the omission with a header.

## Source and evidence

The source now captures the DWORD at offset 0x0C before storing table word
0x0038697C at offset zero. It calls the existing `thunk_FUN_00237ec0` boundary
for original entry 0x002EA018, then clears offsets 0x0C, 0x10, 0x14 and 0x18
after a normal return. The original function signature is unchanged.

The official inventory body remains **18 bytes, 0x002E9C30..0x002E9C41**,
SHA-256 `16F51CE9E39F62C64F480972ECE34344FFD240A259379B37E7FA597D850F01D4`.
A separately hashed 82-byte adjacent program-memory context starts at
0x002E9C30, SHA-256
`0F5C8818C9E8DF592509BD9E6E9654DE506D52B7B51DA0C77DE5687B4D882180`.
Its raw path reaches plain RET at 0x002E9C54. This context does not enlarge the
inventory body, repair Ghidra's stored function definition, or authenticate the
whole original XBE. The CALL_RETURN override is not control-flow evidence.

Machine instruction order is load allocation DWORD, push it, write the table
word, CALL 0x002EA018, XOR EAX,EAX, ADD ESP,4, four stores from zero EAX,

## Bounded validation

The synthetic contract uses seven initialized, live native DWORD words that
remain writable across a normally returning callback. The allocation is opaque
guest32 data, including zero and high-bit values. It is never converted into a
native pointer. Callback changes at offsets zero, four and eight survive; the
four later fields are cleared regardless of the callback's returned DWORD.

Clang C++17 O0/O2 syntax and object checks compile, but never execute, the
canonical uninitialized-register draft. The original missing-declaration
negative and original literal-conversion negative remain active. Initialized
ordinary-DWORD and instrumented-cell projections cover 10,094 cases each at
O0 and O2. Nine incorrect load, argument, missing-store and ordering variants
fail at both optimization levels. GCC UBSan checks both projections at O1.
The fake callback exists only in fixtures; the guest runtime adapter remains
undefined, and a missing-adapter link negative remains required.

Instrumented cells check **C++ source sequencing**, not native emitted
instruction order. Optimized ordinary-DWORD stores may merge or reorder within
this bounded contract. Fault order, MMIO, concurrent observers, arbitrary guest
aliasing, object destruction and address wrapping are excluded. The synthetic
throwing-callback cases test only source sequencing, not Xbox exceptions.

All 37 path bytes have single-byte mutation controls; another 28 controls alter
window addresses/scopes. Exact source and historical preimages are pinned.
Optional private replay checks the 18-byte official body separately from the
82-byte context and independently decodes the 14-instruction path through RET.
Use the raw `heap-free-context-v2/contexts.jsonl` record for replay, not the
enriched per-function diagnostic JSON.

## Separate historical admission

`metadata/cpp_20261104_002e9c30_continuation.json` and
`tools/verify_cpp_002e9c30_continuation.py` define a separate, one-entry channel.
The two original literal ledgers and the earlier five-case heap manifest remain
byte-identical. Their prior allowlists and corruption controls are unchanged.

The canonical historical verifier reverses this continuation before checking
the historical source/inventory fingerprint. It then performs the unchanged
original literal reversal and exact original source/Git-blob checks. Finally,
it reapplies only the continuation edits to that oldest diagnostic preimage.
The old table-word literal operand is independent of every new edit, so the
original pointer-to-integer diagnostic still fails exactly as intended.

Admission pins the manifest, full overlay contents, historical case and ledger,
both source preimages and composed diagnostic source. Wrong-ledger use and
overlap with any of the four earlier channels fail before compilation. The
current source is counted as one additional effective syntax completion; the
historical 209/0 complete/209 partial/469 DWORD ledger counts remain unchanged.
The canonical gate also checks every individual continuation edit reversal.

## Remaining limits

The incoming ECX pseudo-register is still uninitialized and must not be called
as a native function. Guest ESI preservation across the real or dynamically
replaced target is unverified; the projection assumes its object pointer
survives the call. The unchanged void signature does not model the observed
machine EAX=0 at RET. XOR flags are overwritten by ADD ESP,4; EFLAGS, ESP,
other clobbers, stack writes and RET behavior remain unresolved.

The existing 0x002EA018 -> 0x00067BF0 -> guest slot 0x003BC654 path is preserved.
No native `free`, host function-pointer dispatch, heap mapping or fake production
adapter is added. Original-runtime equivalence, whole-function semantics,
byte match and native game linkage are not established. Published syntax counts
still require a completed exact-tree audit.
