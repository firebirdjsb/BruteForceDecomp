# 0x00077eb0 bounded native conversion operation

This batch replaces one unresolved `ABS` draft with a tested **captured-word host operation**. It is not a recovered guest ABI, original-game execution, whole-XBE authentication, or byte-identical rebuild.

## Evidence

The complete original function is 103 bytes / 38 instructions. Its SHA-256 is `8BAE330E7B50ADB10BCF5AD34FC3509582B231AEFF270E5F7550654F10706160`, matching the canonical inventory and independently decoded instruction coverage. No listing overrides were present.

The FCOMP operand at program address `0x003a4fb8` was read as four little-endian bytes `bd 37 86 35`, raw DWORD `0x358637bd`. This was read through an immutable Program view in a fresh copied Ghidra project. All copied-project file hashes were unchanged afterward. The 32-byte context `0x003a4fa8..0x003a4fc7` has SHA-256 `C04F18717657120105F71409BF6DB3130C02EE5D8D2F7351E512CE6046A9F973`. Original FileBytes are absent, so stored executable metadata is not whole-file authentication. No uploaded scripts or original game machine code were executed. Private project/data exports are not repository artifacts.

The original FCOMP reads this absolute memory location on every invocation. The exported bytes establish initial data, not runtime immutability. This fixed-threshold host operation additionally requires that location to retain `0x358637bd`; runtime patching or mutation of the threshold is excluded. The old draft's folded literal is not used as evidence of immutability.

## Bounded behavior

The helper receives captured uint32 kind/input words and writable byte storage. Kind 1 copies four raw bytes, preserving NaN payloads and sign bits without an FP instruction. Kind 2 uses native CVTTSS2SI followed by an integer store; ordinary C++ casts do not implement its invalid-result and exception behavior. Kind 3 retains FLD m32fp, FABS, FCOMP m32fp and FNSTSW in that order. Its one-byte output is zero only for ordered absolute input less than the threshold. Equality, greater and unordered comparisons produce one. Other kinds do not access output.

The helper's returned DWORD models final EAX: raw input for kind 1, conversion result for kind 2, boolean for kind 3, or kind minus three modulo 2^32 otherwise. The canonical wrapper retains its old void(int,float) declaration and unresolved integer-address expressions. It is syntax-checked, not executed; its guest pointer mapping, float argument transport and callers are not repaired by this batch.

Original kind 2 overwrites the PUSH ECX scratch slot with the input word, so final ECX equals that raw word and EDX equals the object pointer. Other branches restore entry ECX and leave EDX unchanged. Every path uses RET 8. These guest register, integer-EFLAGS and stack effects are documented but not implemented by the helper's host ABI.

## Preconditions and exclusions

- GNU/Clang native x86 SSE and x87; no approximate C++ FP fallback; fast math rejected.
- Kind 2 requires all MXCSR exceptions masked. Kind 3 requires all x87 exceptions masked and the specific next push destination, `(TOP - 1) mod 8`, empty. Other paths may use a full x87 stack.
- Valid writable byte extent is four for kinds 1/2, one for kind 3, zero otherwise. Unaligned byte output is supported. No live float-object/alignment assumption.
- Input capture is complete before helper entry. Tests cover overlap with already-captured input storage, not arbitrary aliasing involving original guest stack or object loads.
- Unmasked traps, invalid memory, MMIO, concurrent observers and fault recovery are excluded.

## Validation

An independently authored monolithic native instruction/branch oracle is compared against the helper. It is not execution of extracted instructions. Clang C++17 O0/O2 and GCC C++17 O2 with ASan+UBSan each pass 20,570,112 main comparisons. Leak detection is disabled because the sandbox does not support LeakSanitizer; no leak-check result is claimed.

Coverage includes 558 raw inputs, eight kinds, all three valid x87 precision controls, all four x87 rounding controls, all 16 MXCSR rounding/DAZ/FTZ modes, four live-stack depths and six initial status seeds. Additional tests cover integer-only expected outputs, signed zero, threshold neighbors and negative counterparts, quiet/signaling NaNs, infinities, signed-int32 limits, truncation precision flags, denormal exception behavior, a full x87 stack on non-pushing paths, byte-unaligned buffers, captured-input overlaps, sentinels and exact one/four-byte guarded spans.

The compared state is x87 CW, complete SW, abridged tag, active 80-bit stack payloads and MXCSR. FIP/FDP/FOP differ due to native instruction/data locations and are excluded. Empty-stack payloads, slot padding, XMM register transport, MXCSR_MASK capabilities and reserved fields are excluded. This is not a complete FXSAVE-image or CPU-context comparison.

FXRSTOR declares all XMM and x87 clobbers; FNINIT/seed FILD declare x87 clobbers. FXSAVE capture objects are uninitialized so no memset intervenes. Optimized measured intervals were inspected independently. The focused gate rejects missing FXRSTOR clobbers and checks isolated helper codegen for external calls.

Mandatory public CI includes exact historical source reversal and its old ABS failure at O0/O2, source/helper/oracle hashes, narrow opcode corruption controls, native instruction sequence structure, wrong selector/threshold/raw bits/boolean width, missing FABS and rounded conversion mutations, and unsupported architecture/SSE/fast-math negatives. A private full-body/data-context check is optional and never required for the public gate.
