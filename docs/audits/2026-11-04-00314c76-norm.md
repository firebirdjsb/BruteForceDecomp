# 0x00314c76 native binary80 norm operation

This is a bounded host operation for a valid three-float input buffer. It does not establish guest pointer/register transport, Xbox execution, full-game behavior or a byte-identical rebuild.

## Original evidence and corrected operation

The entire original function is 39 bytes / 17 instructions, SHA-256 `5F4549C0BEC7A3DC6CC1E1BCD1796F1271D397160F7620A1898D617AA5B1EB2B`. Immutable copied-project program memory matches the canonical body digest and exact instruction coverage; no listing overrides were present. Original FileBytes are absent, so the full XBE was not reauthenticated. Neither original machine code nor uploaded scripts were executed.

Original loads occur in z, y, x order. The native stack sequence squares x and y, adds them, then squares and adds z before FSQRT. Intermediate precision and rounding come from the existing x87 control word. Cleanup is FSTP ST3, FSTP ST0, FSTP ST0, leaving the binary80 result in ST0 above the original live stack. Merely binding the old SQRT expression would retain its different addition order.

There is a concrete finite difference: with PC24 and nearest rounding, input words x=`3f800000`, y=z=`39800001` produce binary80 `3fff:8000010000000000` (1 + 2^-23). The reversed draft order produces `3fff:8000000000000000` (1). This is a permanent independent exact anchor and reversed-order negative control.

## Host contract

- GNU/Clang x86-64 Linux with the default SysV ABI and native binary80 long double. Compile-time checks require the native mantissa/exponent properties and IEEE binary32 float. Unsupported architecture/type and fast math are rejected.
- Three live, readable, alignof(float)-aligned float objects. Raw bits, including signed zeros, infinities and NaNs, are allowed. No arbitrary byte-unaligned object claim.
- All x87 exceptions masked. The five specific next physical push destinations, `(TOP - 1)` through `(TOP - 5)` modulo eight, must be empty. Five free slots elsewhere are insufficient. Peak extra occupancy is five; return adds one entry.
- The source keeps its original float10(float*) interface. Original EAX guest pointer preservation and RET4 transport are documented but not implemented. Integer EFLAGS, FIP/FDP/FOP, faults, unmasked traps, MMIO and concurrent observers are excluded.

## Binary80 return boundary

The test invokes the full compiled canonical wrapper, not just the inline helper. An authored out-of-line SysV assembly bridge saves the caller's FP state, installs the seed, CALLs the candidate or independent instruction oracle, and immediately FXSAVEs the returned state. It then restores caller state before its void return. RBX and stack alignment are preserved. This avoids a C++ consumer popping or narrowing ST0 before capture and respects callee-saved CW/MXCSR controls.

At O0, native return plumbing can include FSTPT/FLDT and FLD ST0/FSTP ST0. These were inspected and are included in measured comparisons. The extra copies are not silently assumed harmless:

- Nonzero finite binary32 squares are at least 2^-298. Their nonnegative sum stays below 2^258, with no cancellation. Nonzero square-root results therefore lie between 2^-149 and 2^129, far inside binary80's normal exponent range.
- The original sequence yields zero, normal binary80, infinity or quiet NaN, not binary80 subnormal or signaling NaN. Native80 copies do not narrow these values or add conversion exceptions.
- A return duplicate needs fewer slots than the original five-slot peak. Original cleanup and native return copies clear C1.
- Actual CW/SW/tags/active80 and MXCSR equality is tested on the native host. This is not universal equivalence of undefined condition behavior across every x87 implementation or an original Pentium-III execution claim.

The reviewer found that an earlier capture bridge did not restore caller CW/MXCSR controls and left a result on a void return. This harness issue was fixed before final validation. A permanent regression uses distinct caller/seed controls and active stack values; removing the post-capture caller-state restore must fail.

## Validation and exclusions

Clang C++17 O0/O2 and GCC C++17 O2 with ASan+UBSan each pass 31,850,496 comparisons using the corrected bridge. The matrix contains 432 input triples, three valid x87 precision settings, four x87 rounding settings, 16 MXCSR modes, all eight TOP values, all eight sparse occupancy patterns allowed in the three old-stack positions, and six sticky/status seeds. Extra tests include exact binary80 numerical anchors, the finite addition-order example, input sentinels, a live float array ending exactly at an inaccessible page, caller-state restoration and net return-stack effects.

Compared fields are complete x87 CW/SW, abridged tag, active 80-bit values, and MXCSR. FIP/FDP/FOP are excluded because native instruction/data locations and compiler return-copy opcodes differ. Inactive payloads, slot padding, XMM transport, MXCSR_MASK hardware capabilities and reserved fields are excluded. This is not complete FXSAVE or CPU-context equivalence.

Sanitizers cover compiler-visible C++ operations; inline assembly memory accesses are also checked through guarded spans and sentinels. LeakSanitizer is disabled and untested.

The mandatory public gate pins source/helper/oracle hashes, verifies the historical source fixture and exact reversal, requires the old unresolved SQRT failure at O0/O2, checks narrow opcode windows and codegen, and rejects reversed arithmetic order, missing FSQRT, wrong cleanup, narrowed return and broken caller-state restoration. Private original-body verification is optional and not required by CI. No original body dump or project belongs in Git.
