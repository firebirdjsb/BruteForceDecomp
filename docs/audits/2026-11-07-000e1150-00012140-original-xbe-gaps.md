The 14 omitted bytes after the original `0xE11BA` CALL read a guest pointer from the stack, read and decrement its `+8` counter and write that DWORD back, with stack adjustment. The 18 omitted bytes after the original `0x1215F` CALL write zero to guest offsets `ESI+4` and `ESI+8`, adjust the stack and return. Do not infer that these operations are unreachable solely because the Ghidra body excludes them.

- `0x0001215F`: direct near CALL to `0x002EA018`.
- `0x000E118C`: direct near CALL to `0x0008F690`.

- `0x000E11DC`: `RET 0x10` (callee cleans 16 guest-stack bytes; actual argument identities/aliases still need review).
- `0x002EA018`: original near JMP to `0x00067BF0`; `0x00067BF0`: indirect near JMP through guest memory address `0x003BC654`. The ultimate target and whether it returns are **not** established by the static forwarding bytes.

The matching omission after both calls to the same import-forwarding thunk makes Ghidra's inferred noreturn status a plausible explanation for the source-body gaps, **but this inference is not verification of actual runtime behavior**. The original caller's cleanup would be important **if** the imported function returns. Conversely, forcibly adding a return to an unknown import is not acceptable for 1:1 reconstruction.
