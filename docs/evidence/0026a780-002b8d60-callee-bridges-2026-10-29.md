## Callee 0x0026A780: original 136-byte scale and copy

Body SHA-256:
`2e3f69e58906705fb693da7ff568ed43f814ccf0bfeac043799486d1e7fed2fa`.

- On entry, EBX is the **implicit weights vector**. Stack arguments
  `[entry_ESP+4]` and `[entry_ESP+8]` contain the destination and
  matrix-parameter object respectively. Object offsets +0x510/+0x514
  contain the original row and column counts.
- The original `SUB ESP,0x51C; PUSH ESI; PUSH EDI` and conditional
  `PUSH EBP` create the guest frame; the multiplication starts at
  `[entry_ESP-0x518]`. Original stores in that frame do not
  initialize all its words.
- Each entry is `FLD m32fp [EBX+col*4]; FMUL m32fp
  [object+row*0x48+col*4]; FSTP m32fp [frame+row*0x48+col*4]`.
  Each iteration reads the guest operands in the actual instruction
  order; backend callbacks own x87 precision, control, status and traps.
- The original remaining-row count is a guest DWORD; the source
  reloads it at 0x26A7DC and decrements it at 0x26A7E4.
  ESI is also reloaded from `[entry_ESP+8]` each nonempty row.
- The final **`REP MOVSD` 0x146 DWORDs** begins at
  `[entry_ESP-0x518]`. The operation copies raw guest words,
  including *unwritten/uninitialized bytes*, in DF-controlled order.
  It is not `memcpy` or `memmove` and preserves forward-overlap
  propagation, partial faults and potential overwrite of a return
  address or saved registers.
- The bridge at `src/guest_cpu/bf_0026a780_guest_scale.h`
  captures guest32 return EIP/ESP and popped EBP/EDI/ESI; it does not
  convert guest addresses directly into host pointers.

`src/guest_cpu/bf_00269600_scale_call.h` composes the authentic
`0x002696AD..0x002696C3` two PUSHes and CALL to 0x0026A780,
using the verified register/stack contract from
`bf_00269600_downstream_calls.h`. The adapter verifies the
callee's next EIP is the expected 0x002696C3 and the restored guest
ESP equals the caller's actual post-return ESP. It also handles
diagnostic CALL-push and callee read/write faults.

The isolated C11 test covers 28 row/column patterns, empty matrix
copy, raw untouched frame words, fault injection, both direction-flag
paths, and forward overlapping memory. The caller bridge adds
argument/return and output-alias tests. Focused Clang `-O0`, `-O2`,
ASan and UBSan completed successfully in GitHub Actions run
`40976387417`.

## Callee 0x002B8D60: two original guest allocations

Body SHA-256:
`e10ff4f6c4d1b02768c5ea17a970b2c996d18356bc42c5fe5bb0756b77ebb76f`.

- Incoming registers: EAX is the 32-bit requested element count;
  ESI is the output object's five-word guest address. EBX/EDI are
  saved by original PUSH/POP instructions.
- First indirect call at 0x2B8D7F reads target pointer at
  `[0x003BC650]`, pushes count`<<2`, and then executes original
  zero-fill using `REP STOSD`.
- The original `[ESI]` is **re-read after the first zero-fill**.
  This matters when the first allocation aliases the output object;
  the second requested size is that re-read value`<<3`. The
  second indirect call at 0x2B8DA4 re-reads the allocator target.
- Zero-fill direction follows guest DF, with all accesses going
  through explicit guest memory. Both original STOSB remainder counts
  are zero because byte counts are multiples of four, even after
  32-bit wraparound.
- Original object stores: `[ESI]` count;
  `[ESI+0x0C]` first allocation;
  `[ESI+0x04]` second allocation;
  `[ESI+0x08]` second allocation + 4*re-read count;
  `[ESI+0x10]` zero. The original function returns EAX=ESI
  and restores guest ESP from the call stack.
- **Allocator identity and behavior are still unresolved.**
  `src/guest_cpu/bf_002b8d60_guest_alloc.h` requires an explicit
  guest callback to recognize the indirect target and allocate a
  guest address. Unit tests use a labeled synthetic allocator, not a
  claim that a particular Xbox XDK API has been recovered.

`src/guest_cpu/bf_001f3aa0_allocator_call.h` connects original
`0x001F3B31..0x001F3B4A` to this callee: size 8, destination at
`live_ESP+0x90`, original `[ESP+0x40]=0x0039EFC8`,
CPU-pushed return EIP 0x001F3B4A. On successful return, the wrapper
checks ESP restoration and the object address, and the test then
executes the independently verified 256 sparse four-byte writes at
32-byte intervals. The allocator output structure is therefore
represented as *real guest memory* rather than a guessed C local.

The 0x2B8D60 tests cover 32 bounded sizes, 32-bit wraparound,
indirect allocator failure, partially written data, DF, aliasing
between the first allocation and object, and changed return EIP.
Both isolated and 0x001F3AA0 caller-composition tests passed
Clang `-O0`, `-O2`, and ASan/UBSan in GitHub Actions run
`40976947345`.

## Remaining original-body and 1:1 gates

1. Resolve the authentic allocator target(s) in `[0x003BC650]`
   and verify their stack/heap/guest-memory contracts.
2. Reconstruct `0x00269870` (factorization), `0x0026A810`
   (matrix product), and `0x002B7970` (vector x87/SSE) before
   claiming the original higher-level callers are fully rebuilt.
3. Validate whole-function path-sensitive state, 80-bit x87 control,
   SSE/MXCSR rounding, guest EFLAGS, error/SEH and indirect calls
   against the original Xbox semantics.
4. Only then replace the original `FUN_00269600`,
   `FUN_0026A780`, `FUN_001F3AA0` and
   `FUN_002B8D60` drafts with a correctly connected C11 runtime.
   A syntax-only change cannot establish original 1:1 behavior.
