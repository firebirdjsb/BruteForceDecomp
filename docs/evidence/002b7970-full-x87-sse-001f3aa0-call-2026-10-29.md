# 0x002B7970 complete guest operations and 0x001F3B2C call connection

Date: 2026-10-29. Original user-provided Xbox Brute Force executable
SHA-256: `b6ea5d4dd6500ae86c3f5e3e4618bc9b1e3facddcb483170dfee7a787087c721`.

**Scope:** original instruction-ordered C11 guest operation bridge, tested
caller link, but **not** a full Xbox FPU/SEH verification and **not**
a newly syntax-passing Ghidra source function.

## Original evidence

The original complete 0x002B7970..0x002B7AEF machine-code body is
384 bytes. SHA-256:
`0c66011a1ef28b7d259dc354572bad0594545ba5b2d1a1b9006420e2753d3d72`.

`scripts/verify_002b7970_complete_xbe.py` checks the whole original
XBE SHA, the full 384-byte body, and **33 original opcode windows**
(including the 0x001F3B2C CALL and 0x002B7AED RET 8). This was
executed against the user's original XBE and passed, independently of
the GitHub Actions synthetic execution tests. The original game
executable is never committed.

Previously `src/guest_cpu/bf_002b7970_guest_base.h` handled the
0x002B7970..0x002B7A2D guest x87/vector setup. The new
`src/guest_cpu/bf_002b7970_guest_tail.h` completes the remaining
original instructions:

- `0x002B7A31` FLD m32fp of destination+4, `0x002B7A37` FMUL
  m32fp at original Xbox VA 0x003A4F74, `0x002B7A48` FSTP into
  original 4-byte guest stack scratch slot.
- `0x002B7A50..0x002B7A80`: first `MOVSS`, `MOVHPS`,
  `SHUFPS 0`, `MULPS`, `ADDPS`, `MOVSS`, `MOVHPS` path.
  It scales the destination+0x40 vector by the x87-derived scalar,
  adds it to destination+0x30, and stores lanes 0, 2 and 3.
- `0x002B7AA4..0x002B7AD4`: second packed-SSE path using
  original destination+4 as the scalar, destination+0x40 as the
  source vector, and destination+0x10 as the addend. Original output
  is destination+0x20.
- Original scalar `MOVSS` overwrites only lane 0, leaving XMM lane
  1 intact. `MOVHPS` overwrites lanes 2 and 3. Both SSE arithmetic
  operations still process the preserved lane 1 internally: the
  second packed operation uses lane 1 from the first. Four raw
  32-bit lanes are passed into the backend, even though the original
  memory stores omit the second lane.
- Original `MOVHPS m64` guest memory reads and writes use one
  64-bit guest callback, rather than two independent host DWORD
  operations. Faults retain prior completed writes, while actual
  Xbox SSE fault restart and guest exception state remain backend-owned.
- `0x002B7ADC` zeros destination+0x2C, `0x002B7AE3` zeros
  destination+0x0C, and `0x002B7AED` executes `RET 8`.
  All final writes remain in their true original instruction order.
  Successful guest ESP becomes call-entry ESP+12; next guest EIP
  comes from the original return word, and EAX is the output guest VA.

`src/guest_cpu/bf_002b7970_guest_complete.h` composes the
existing base and new tail with **one x87 context** and one guest
memory interface. It refuses mixing separate FPU contexts.

## Connected original caller

`src/guest_cpu/bf_001f3aa0_vector_call.h` accepts the **actual**
`bf_001f3aa0_make_2b7970_args` output, not guessed host pointer
arguments. It checks the verified callsite address relationships:

- Live guest ESP `L` immediately before the two original PUSHes.
- Original first callee argument at `[L-8]` is `L+0x40`.
- Original second callee argument at `[L-4]` is `L+0x18`.
- The CPU CALL pushes `0x001F3B31` to `[L-12]`.
- `RET 8` restores guest ESP to `L`, next EIP to
  `0x001F3B31`, and EAX to `L+0x40`.

The original source draft `src/main_unclassified/band_001f/0x001f3aa0.c`
is not rewritten yet. The caller still has subsequent allocation,
sparse guest-frame and x87 work, and its implicit entry-register ABI
has not been fully linked to a native guest CPU state.

## Executed tests and limitations

Focused GitHub Actions `40980862854` passed at Clang ISO C11
`-O0` and `-O2`, as well as ASan and UBSan:

- `tests/test_002b7970_guest_tail.c`: **40,584 assertions per
  optimization setting**, with host SSE intrinsics, preserved lane 1,
  original output arithmetic on bounded inputs, 64-bit memory fault
  injection, x87 scratch writes and final RET 8.
- `tests/test_001f3aa0_vector_call.c`: **6,814 assertions per
  optimization setting**, covering caller PUSH/return handoff and
  complete base+tail execution.
- `tests/test_001f3aa0_producer_to_vector.c`: **15,618 assertions
  per optimization setting**, now invoking the genuine original
  0x001F3AA0 guest x87 producer before CALL, not a mocked producer
  output. It checks generated input slots, output fields and the
  return-address/ESP contract.

These tests establish focused address, operation ordering and bounded
arithmetic results. They do **not** establish bit-identical Xbox
x87 FPU control/status, SSE MXCSR/denormal modes, signaling-NaN
payloads, original guest EFLAGS, fault restart/SEH behavior,
virtual-call/linkage or a native PC application. Host x87-style
long-double approximations and SSE intrinsics are test references,
not a certified Xbox CPU oracle.

**Syntax progress is separate.** The latest published full-tree Clang
inventory remains 13,636/13,694 passing, 58 failing (99.58%),
with zero original body-hash mismatches. The original higher-level
C11 Ghidra draft bodies were deliberately not replaced with
speculative host pointer/register approximations to inflate coverage.
