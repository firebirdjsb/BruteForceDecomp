## Two original parser caller handoffs now linked in isolated C11

`include/bf_001feb60_caller_dispatch.h` invokes the existing
`bf_001feb60_execute` with the original 32-bit register/address inputs:

| Original caller | EAX | EBX | ESI | EDI |
|---|---|---|---|---|
| `0x001FF0F0` | `ESP+0x14` | `ESP+0x10` | selected filter guest VA | owner guest VA |
| `0x002058C0` | `ESP+0x14` | `ESP+0x10` | selected filter guest VA | owner guest VA |

Here ESP is **live immediately before** the original `CALL 0x001FEB60`,
not the callee ESP after the return-address push. AL is tested for
success; the original caller reads `[ESP+0x10]`, then `[matched+8]`.
No invented `uRam00000008` RAM symbol or literal VA 8 is used.

The dispatch path is different in the two callers:

| Original caller | Type adjustment | Unsigned max index | Byte table | Target table | Out-of-range target |
|---|---|---|---|---|---|
| `0x001FF0F0` | `raw-2` | `0x2A` | `0x001FF494` | `0x001FF464` | `0x001FF438` |
| `0x002058C0` | `raw-4` | `0x1F` | `0x00205A48` | `0x00205A28` | `0x002059C2` |

The adapter reads one guest byte from the source byte table and a guest
DWORD from its target table; it returns the original jump target rather
than performing a guessed host control transfer. It returns the
original end-of-iterator case when AL is zero and propagates diagnostic
read/write failures without claiming guest exception/SEH restart.

`tests/test_001feb60_caller_dispatch.c` exercises 12
original-type/target cases across 256 repetitions, branch bypass,
matched-output and cursor updates, direct out-of-range jumps, empty
iteration, read/write/byte failure cases and refusal of unsupported
caller identities. Dedicated CI checks Clang ISO C11 -O0 and -O2.
The workflow passed on commit `35916bf` (run `40964655035`).

`tools/verify_001feb60_caller_dispatch_xbe.py` is a private local
verifier for the original XBE's 77-byte iterator body, both byte tables,
both jump-pointer tables, and 14 original CALL/type-read/branch-table
instruction windows. It commits only hashes/opcode fingerprints, not
copyrighted game data.

**Boundary:** Both original source functions `FUN_001FF0F0` and
`FUN_002058C0` are intentionally unchanged. Their original host-ABI
register setup, case-body callbacks and native linkage have not been
verified; the bridge does not itself remove their C11 syntax errors.

## Seven original scalar SSE windows at 0x00155840

`include/bf_00155840_scalar_sse.h` implements a separate original
scalar lane operation and guest `MOVSS` store for these windows:

| RSQRTSS/SQRTSS instruction | Original source | MOVSS destination |
|---|---|---|
| `0x001559EA` RSQRTSS | `[EBP-0x1C]` | `[EBP-0x18]` |
| `0x00155A36` RSQRTSS | `[EBP-0x1C]` | `[EBP-0x18]` |
| `0x00155AEA` RSQRTSS | `[EBP-0x1C]` | `[EBP-0x18]` |
| `0x00155B4A` RSQRTSS | `[EBP-0x1C]` | `[EBP-0x18]` |
| `0x00155BAB` SQRTSS | `[EBP-0x18]` | `[EBP-0x10]` |
| `0x00155C28` RSQRTSS | `[EBP-0x1C]` | `[EBP-0x18]` |
| `0x00155CA9` RSQRTSS | `[EBP-0x1C]` | `[EBP-0x10]` |

The source is the original XBE, not decompiler pseudocode. The bridge
retains raw XMM0 upper 96-bit lane words across each operation and
delegates the low-lane arithmetic to a dedicated SSE backend, avoiding
an incorrect exact `1/sqrtf` approximation claim. It reads the source
DWORD before executing SSE and writes the one output DWORD after.
Tests use real host SSE intrinsics for thousands of bounded examples,
plus failures before/after the scalar operation. The original console
RSQRTSS numeric approximation, MXCSR/denormal/NaN payload behavior and
fault restart remain unverified.

`tools/verify_00155840_scalar_sse_xbe.py` checks the pinned caller
body SHA and all fourteen original machine-code instruction windows.
The ISO C11 tests are part of the focused x87 GitHub Actions workflow.
