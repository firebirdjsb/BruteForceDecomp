## 0x00269600: corrected REP pre-call stack

The original instruction sequence contains `LEA EAX,[ESP+0x60]` at
`0x00269637` and `PUSH EAX` at `0x0026963B`, *between*
`REP STOSD` at `0x00269627` and `REP MOVSD` at `0x0026963C`.

The original EDI destination for MOVSD is calculated **before** this
push and does not move, but live ESP decreases by four. At
`0x0026963E`, `LEA ECX,[ESP+0x14]` therefore points to the
old `ESP+0x10`. The isolated prefix implementation and regression
test now replay this guest PUSH, including its fault boundary.
The existing 0x00269600 case `[ESP+0x58]` alias remains preserved.

## 0x00269600: x87 comparison and reciprocal loop

`src/guest_cpu/bf_00269600_x87_loop.h` reconstructs the
`0x0026965F..0x002696AD` guest-memory and ordered x87 operations.
In the loop, the original:

- `FLD m32fp [ESP+ECX*4+0x10]`;
  `FCOMP m64fp [0x003A5100]`;
  `FNSTSW AX`.
- `TEST AH,0x05; JP`, **not** an ordinary C `>=` test.
  Both status bits clear or both set take JP. This includes unordered
  comparisons when AH bits 0 and 2 are both set. Each original
  FLOAT64 comparison operand is read in a single guest 8-byte access.
- On the parity branch, `FLD m32fp [0x003A4F78]`,
  `FDIV m32fp [ESP+ECX*4+0x10]`, increment the guest count at the
  original `[EBP+0x0C]` output, then `FSTP` the result into the
  original stack element. On the other branch write zero.
- Re-read `[EBX+0x514]` after every element and advance original
  ECX, preserving possible guest alias changes to the count.

An explicit x87 backend owns actual 80-bit arithmetic, status/control,
exceptions and guest trap delivery. Tests use a bounded host reference,
not a claim of Xbox NaN payload or x87 precision equivalence.
Focused CI at `-O0` and `-O2` passed **167 assertions** per
configuration, including unordered status parity, reciprocal writes,
zero count and guest fault prefixes, plus ASan/UBSan.

## All three original 0x00269600 downstream call boundaries

`src/guest_cpu/bf_00269600_downstream_calls.h` derives the exact
callee guest stack arguments and register inputs for the three
original calls. Let `S` be the live guest ESP after the first
callee `0x00269870` returns:

| Callee | Original call | Guest args (from first argument) | Callee return and caller cleanup |
| --- | --- | --- | --- |
| `0x00269870` | `0x0026965A` | `EBX`, `S+0x578`, `S+0x10`, `S+0x60` | `RET 0x10` at `0x0026A778`; restores ESP to `S` |
| `0x0026A780` | `0x002696BE` | `S+0xA90`, `S+0x60`; EBX implicit `S+0x10` | Plain `RET` at `0x0026A807` |
| `0x0026A810` | `0x002696DB` | `S+0xFA8`, `S+0xA90`, `S+0x578` | Plain `RET` at `0x0026A8F5`; then original caller `ADD ESP,0x14` |

All address calculations are unsigned 32-bit guest arithmetic. The
`0x0026A780` implicit EDX value is **not asserted** (the known
register mask excludes it). No method body, allocation result, or
indirect target is inferred. The original `0x0026A810` EAX return
still requires its true callee-side output contract before being
connected to the 0x146-DWORD caller output copy.

The focused CI passed **20,056 assertions** per optimization setting,
including original ABI arguments and all three stack-cleanup paths.

`scripts/verify_00269600_x87_downstream_xbe.py` pins the original
function-body hashes for `0x00269600`, `0x001F3AA0`,
`0x0026A780` and `0x0026A810`, plus the relevant machine-code
instructions, CALL opcodes and RET cleanup. These were independently
checked against the private XBE without uploading it.

## 0x001F3AA0: actual data producer before 0x002B7970

`src/guest_cpu/bf_001f3aa0_guest_producer.h` replays verified original
instructions at `0x001F3AB0..0x001F3B31`.
The original input object is incoming ECX, and `EDI=ECX`.
It reads `[EDI+0x38]`, `[EBP+0x08]`, `[EBP+0x0C]`
and produces two ordered x87 expressions:

1. `FLD m32fp [object_data+4]; FADD m32fp [0x003A4F78]; FSTP m32fp [ESP+0x1C]`.
2. `FLD m32fp [object_data+4]; FSUB m32fp [object_data+8]; FADD m32fp [0x003A4F78]; FSTP m32fp [ESP+0x38]`.

The helper also replays the original raw stack writes including
`0xBF800000`, `0xFF7FFFFF`, and the two original PUSH arguments.
It accepts only the verified guest ESP:
`(guest_EBP & ~15) - 0x20B0`.
The two pointers at original CALL `0x002B7970` are
`live_ESP+0x40` and `live_ESP+0x18`. Callee `0x002B7970`
returns using `RET 8` at `0x002B7AED`.
It calls no guessed allocator or downstream method.

Focused tests passed **7,999 assertions** per optimization setting at
`-O0` and `-O2`, plus ASan/UBSan. They verify exact guest word
addresses, the two floated results on bounded finite inputs, argument
ordering, partial fault effects, and refusal of a wrong guest ESP.
`scripts/verify_001f3aa0_producer_xbe.py` independently checks
seventeen original instruction/return windows against private XBE.
