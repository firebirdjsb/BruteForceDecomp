# 0x000E7780 — x87 caller-stack word and condition repair (2026-10-23)

The exact original XBE is identified by SHA-256 `B6EA5D4DD6500AE86C3F5E3E4618BC9B1E3FACDDCB483170DFEE7A787087C721`; no proprietary binary is added to this repository.

- Function entry `0x000E7780`, original length **205**, original body digest `D48F98CF94C27BE699B0002C1C9B602AF388EED99E86CFB0749A67A30AA108E8`.
- Entry saves the caller's first stack argument in `EBP` (`0x000E7784`) for later pointer dereferences. The same original caller stack word is subsequently read as **m32fp** at `0x000E781E` (`fcom`) and `0x000E7839` (`fsub`) after conditional modification by the helper or zeroing.
- Original `fcom`, `test ah,0x05`, `jp` selects the subtract branch on greater, equal **or unordered** results; the C11 draft now uses `!(fVar1 < threshold)` to reflect that branch classification. This does **not** establish identical x87 exceptions/precision on PC.
- The preexisting `(float)param_1` was a numeric pointer-to-float conversion. The source now takes the **low 32-bit stored word** of the original argument slot and reinterprets it as `float` via C11 `memcpy`. A shared `bf_x86_word_to_f32` helper is unit-tested with round-trips and special values.

**Unverified:** incoming EAX/EBX registers, ESI/EDI helper contract at `0x00022BC0`, the virtual call through EAX, x87 arithmetic order/precision, caller stack layout under host 64-bit pointers, correct final object/output data, linking and in-game behavior. Preserving the original 32-bit lane here is a **source-level improvement only**, not a native PC port or a full 1:1 recreation.
